# Address Book

## Backend

The backend is built with **FastAPI** and handles API requests from the frontend, validates contact data, communicates with the database, and returns responses to the client.

### Technologies

- **FastAPI** — Python framework used to create the REST API and define the application's endpoints.
- **Uvicorn** — ASGI server used to run the FastAPI application.
- **Pydantic** — Defines the expected structure of request and response data and validates incoming contact information.
- **SQLAlchemy** — ORM (Object Relational Mapper) used to communicate between the Python application and SQLite.
- **SQLite** — Lightweight relational database used to persist contact information.

### Backend Structure

```text
backend/
├── main.py
├── requirements.txt
└── address_book.db
```

**`main.py`** contains the database configuration, SQLAlchemy model, Pydantic models, FastAPI configuration, and REST API endpoints.

**`requirements.txt`** contains the Python packages required to run the backend.

**`address_book.db`** is the SQLite database file. It is created when the backend runs and allows contact information to persist after the browser or server is restarted.

### Database

The application uses a single `contacts` table.

Each contact contains:

```text
id          INTEGER PRIMARY KEY
name        TEXT
email       TEXT
phone       TEXT
street      TEXT
city        TEXT
state       TEXT
zip         TEXT
created_at  DATETIME
```

The `id` is an integer primary key generated by SQLite when a contact is inserted. The frontend does not create or send an ID when creating a new contact.

After inserting the contact, the backend refreshes the SQLAlchemy object so that the generated `id` and `created_at` values can be returned to the client.

Duplicate contacts are allowed. The `id` is used to uniquely identify individual records.

### SQLAlchemy

SQLAlchemy acts as the ORM between FastAPI and SQLite.

The `Contact` SQLAlchemy model defines how contacts are represented in the database:

```python
class Contact(Base):
    __tablename__ = "contacts"

    id = Column(Integer, primary_key=True, index=True)
    name = Column(String, nullable=False)
    email = Column(String, nullable=False)
    phone = Column(String, nullable=False)
    street = Column(String, nullable=False)
    city = Column(String, nullable=False)
    state = Column(String, nullable=False)
    zip = Column(String, nullable=False)
    created_at = Column(DateTime, default=datetime.utcnow)
```

Instead of writing raw SQL for every operation, the application can interact with contacts through Python objects and SQLAlchemy queries.

For example:

```python
db.query(Contact).all()
```

retrieves contacts from the SQLite database.

### Pydantic Models

Pydantic models define the structure of data accepted and returned by the API.

`ContactCreate` contains the fields that the client is allowed to provide:

```python
class ContactCreate(BaseModel):
    name: str
    email: EmailStr
    phone: str
    street: str
    city: str
    state: str
    zip: str
```

Because `id` and `created_at` are not part of `ContactCreate`, the client cannot set these values when creating or updating a contact.

`ContactResponse` includes the database-generated fields:

```python
class ContactResponse(ContactCreate):
    id: int
    created_at: datetime
```

This separates the structure of incoming data from the structure of outgoing API responses.

### REST API

The backend exposes the following endpoints:

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/contacts` | Retrieve all contacts |
| `GET` | `/contacts/{contact_id}` | Retrieve one contact |
| `POST` | `/contacts` | Create a new contact |
| `PUT` | `/contacts/{contact_id}` | Update an existing contact |
| `DELETE` | `/contacts/{contact_id}` | Delete a contact |

The API follows REST conventions by using HTTP methods to describe the operation being performed on the `contacts` resource.

### Creating a Contact

When the frontend sends:

```text
POST /contacts
```

with a JSON contact, the backend:

1. Receives the HTTP request through FastAPI.
2. Uses Pydantic's `ContactCreate` model to validate the request body.
3. Creates a SQLAlchemy `Contact` object from the validated data.
4. Adds the new object to the database session.
5. Calls `db.commit()` to persist the row in SQLite.
6. Calls `db.refresh()` to retrieve database-generated values such as the contact ID.
7. Serializes the contact using `ContactResponse`.
8. Returns the new contact as JSON with an HTTP `201 Created` response.

The core operation is:

```python
new_contact = Contact(**contact.model_dump())

db.add(new_contact)
db.commit()
db.refresh(new_contact)

return new_contact
```

The flow can be summarized as:

```text
React
  ↓
POST /contacts
  ↓
FastAPI
  ↓
Pydantic validation
  ↓
SQLAlchemy
  ↓
SQLite
  ↓
ContactResponse
  ↓
JSON response
```

### Updating a Contact

Updates use:

```text
PUT /contacts/{contact_id}
```

The backend first searches for the requested contact ID.

If the contact does not exist, the API returns:

```text
404 Not Found
```

with:

```json
{
    "detail": "Contact not found"
}
```

If the contact exists, only the fields defined by the Pydantic request model are updated. The `id` and `created_at` fields cannot be changed through the update request.

The changes are then committed to SQLite and the updated contact is returned to the client.

### Persistence

Contact data is stored in SQLite rather than React state or browser storage.

This means refreshing the page does not delete the contacts. When the frontend reloads, it sends another `GET /contacts` request to FastAPI. FastAPI queries SQLite and returns the persisted contacts.

```text
Browser refresh
      ↓
React restarts
      ↓
GET /contacts
      ↓
FastAPI
      ↓
SQLite
      ↓
Saved contacts returned
```

### Running the Backend

Install the backend dependencies:

```bash
pip install -r requirements.txt
```

Start the FastAPI server:

```bash
uvicorn main:app --reload
```

The API runs locally at:

```text
http://localhost:8000
```

FastAPI's interactive API documentation is available at:

```text
http://localhost:8000/docs
```
